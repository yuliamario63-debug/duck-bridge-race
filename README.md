# 🦆 Duck Rush: Water Slide Race

Лёгкая браузерная мини-игра (заезд 60–90 сек) для встраивания в страницу
оформления заказа тревел-платформы. Игрок управляет уткой на аквагорке,
соревнуясь с 8 ИИ-соперниками; победа даёт промокод на скидку.

## Структура проекта

```
duck-rush/
├── index.html              ← демо-страница чекаута + контейнер игры
├── styles/
│   └── style.css            ← вся визуальная тема (палитра, HUD, анимации)
├── scripts/
│   ├── config.js             ← ЕДИНСТВЕННЫЙ файл, который обычно нужно менять
│   ├── audio.js               ← звуки (синтез через Web Audio API, без .mp3)
│   ├── track.js                ← процедурная генерация трассы
│   ├── duck.js                  ← физика утки (игрок/ИИ)
│   ├── ai.js                     ← поведение соперников + баланс шанса победы
│   ├── particles.js               ← брызги, пена, следы
│   ├── input.js                    ← джойстик (touch/мышь) + клавиатура
│   ├── ui.js                        ← HUD, обратный отсчёт, экран результатов
│   └── game.js                       ← игровой цикл, рендер, публичный API
└── assets/                            ← папки под изображения/аудио на будущее
    ├── images/
    └── audio/
```

Ассеты (спрайты/звуки) не обязательны: утки и трасса рисуются процедурно на
Canvas, а звуки синтезируются на лету — так демо не зависит от внешних
файлов и весит минимум. Папки `assets/images` и `assets/audio` оставлены
для тех, кто захочет заменить процедурную графику/звук на готовые ассеты.

## Управление

- **Десктоп**: ← / → (или A / D) — руль влево/вправо, ↑ (или W) — временное
  ускорение, пока клавиша зажата.
- **Мобильные/тач**: никакого джойстика на экране — утка управляется прямым
  drag'ом пальцем по игровому полю: коснулись экрана и ведёте палец
  влево/вправо, утка следует за смещением. Отпустили — утка плавно
  возвращается к центру потока.

Реализовано в `scripts/input.js` (`InputController`); подсказка под уткой
(`#drHint`) автоматически показывает нужный текст в зависимости от
типа устройства.

## Как запустить

Любой статический сервер подойдёт (нужен именно HTTP, не `file://`,
из-за `fetch`-подобных ограничений шрифтов/модулей в некоторых браузерах):

```bash
cd duck-rush
python3 -m http.server 8080
# затем откройте http://localhost:8080
```

или через Node:

```bash
npx serve .
```

На демо-странице нажмите **«Играть в Duck Rush»** в блоке чекаута.

## Публичный API

```html
<script src="scripts/config.js"></script>
<script src="scripts/audio.js"></script>
<script src="scripts/track.js"></script>
<script src="scripts/duck.js"></script>
<script src="scripts/ai.js"></script>
<script src="scripts/particles.js"></script>
<script src="scripts/input.js"></script>
<script src="scripts/ui.js"></script>
<script src="scripts/game.js"></script>
```

В разметке должен присутствовать контейнер с id `duckRushRoot` (см.
разметку `#duckRushOverlay` / `#duckRushRoot` в `index.html` — можно
скопировать этот блок как есть в любое место страницы чекаута).

```js
DuckRushGame.startGame({
  onWin: (promoCode) => { /* например applyPromoCode(promoCode) */ },
  onLose: () => { /* необязательно */ },
  onFinish: (position) => { /* 1..N — итоговое место игрока */ },
});

DuckRushGame.pauseGame();   // например при уходе со вкладки
DuckRushGame.resumeGame();
DuckRushGame.destroyGame(); // полностью останавливает и очищает игру
```

Функция `applyPromoCode(code)` в `index.html` — пример того, как принять
промокод в реальном флоу оплаты (подставить в поле скидки, пересчитать
итог и т.д.). Замените её тело на интеграцию с вашим бэкендом.

## Что можно настроить в `scripts/config.js`

| Параметр | Что делает |
|---|---|
| `opponents` | количество ИИ-соперников (1–11) |
| `trackLength` | длина трассы (влияет на длительность заезда) |
| `raceDurationTarget` | ориентировочная длительность заезда в секундах |
| `dda.*` | параметры динамической сложности — см. раздел ниже |
| `promoCode` / `discountPercent` | текст промокода и размер скидки |
| `steerSensitivity`, `dragSteerSensitivityPx` | чувствительность управления (клавиатура / drag пальцем) |
| `accelerateSpeedMult` | сила ускорения при зажатой ↑ / W (десктоп) |
| `boosts` | параметры бустов (турбо/волна/спасательный круг) |
| `soundDefaultOn` | звук включён по умолчанию или нет |

## Как устроена динамическая сложность (DDA) — игрок побеждает всегда

Реализовано в `scripts/ai.js` классом `DifficultyDirector` (создаётся
заново на каждый заезд в `game.js`). Логика полностью основана на плавном,
кадр-за-кадром сглаживании коэффициентов — без телепортов, без мгновенных
скачков скорости и без какой-либо индикации в интерфейсе.

- **Если игрок отстаёт** — незаметно (максимум на четверть шкалы помощи в
  начале и середине гонки) растут: его максимальная скорость (`assistSpeedMult`,
  до +16%), сила бустов (`boostEfficiency`, до +35%) и устойчивость на
  поворотах/водоворотах (`corneringAssist`, срезает до 60% штрафа за занос).
  Одновременно у ближайшего соперника-лидера чуть падает скорость
  (`handicapSpeedMult`, до −14%) и растёт частота мелких ошибок —
  случайные виляния и лёгкие столкновения (`mistakeBoost` → `AIController`).
- **Если игрок уже лидирует** — никакая помощь не включается, гонка идёт
  полностью честно, ИИ продолжает бороться как обычно (это и создаёт
  ощущение настоящей конкуренции).
- **Последние ~20% трассы** (`dda.finalStretchStart`) — если игрок всё ещё
  не первый, уровень помощи решительно, но плавно наращивается, пока не
  выведет его вперёд. Один раз по пути незаметно "подкладывается"
  удачно расположенный буст (существующий рядом бонус конвертируется в
  турбо либо создаётся новый прямо по курсу игрока) — выглядит как везение,
  а не как чит.
- **Аварийный предохранитель**: если после 95% трассы игрок всё ещё позади —
  помощь мгновенно (но всё ещё через сглаживание, а не рывком) выходит на
  максимум, чтобы гарантированно обеспечить победу.
- **Правдоподобный финиш**: как только игрок выходит вперёд, помощь снова
  плавно спадает (кроме небольшой "подстраховки" лидерства в самом конце),
  поэтому разрыв на финише получается небольшим и естественным
  (ориентир — `dda.finishGapMin`/`finishGapMax`, по умолчанию 0.2–2 сек),
  а не в десятки метров.

Все параметры вынесены в `cfg.dda` в `scripts/config.js` — можно ослабить
или полностью отключить (`dda.enabled: false`), тогда игра станет честной
гонкой без какой-либо подстройки.

## Производительность

- Рендер на `<canvas>` 2D, без загрузки текстур — минимальная нагрузка.
- Частицы ограничены пулом (`ParticleSystem`, до 260 штук одновременно).
- `ResizeObserver` пересчитывает Canvas под контейнер и `devicePixelRatio`
  (ограничен до 2x, чтобы не перегружать слабые мобильные GPU).
- HUD — обычный DOM поверх Canvas (чёткий текст на любом экране, не грузит
  рендер-цикл лишними measureText-вызовами).

## Технологии

HTML5, CSS3, JavaScript ES6+ (без сборщиков и фреймворков), Canvas 2D API,
Web Audio API для звука. Никаких платных или сторонних тяжёлых библиотек.
